# RTX 4080 SUPER (sm_89) 优化探测 — 2026-10-23

对 `ninfer:1.7.0-sm89` + `Qwen3.8-27B-GSQ-RCO-IQ3_S-ninfer-v3.ninfer`
(13.4 GiB,int8 KV,`--spec dflash2 --draft-tokens 5 --lm-head-draft`,
`--prefill-chunk 2048`)做配置扫描 + 三层 profiling,结论:**生产配置已最优,
decode 已打到带宽墙,剩余空间只有 ~10% 的引擎级轮间流水线,无快速核级补丁**。

## 1. 配置扫描(5 组,数据 `bench/v100/data/sm89_opt_2026-10-23/runs.txt`)

| 配置 | decode (long/short) | 结论 |
|---|---|---|
| **ch2048 K5 int8(生产)** | 93.8 / 57.9 | 基线 |
| ch4096 | 94.7 / 57.0 | 噪声内,chunk 对 4080S 无影响 |
| ch8192 | 88.4 / — | 更差 |
| K7 | 81.6 / — | 接受率 27.1%(< K5 的 36.0%),更差 |
| bf16 KV | 77.4 / — | 更差 |

与 V100 不同:4080S 上 prefill chunk 大小没有可测影响(27K prefill 1.86-1.92k
tok/s 全组一致),生产配置保持不动。

## 2. decode 相位分解(nsys `--cuda-graph-trace=node`)

关键方法学:默认 nsys 不展开 CUDA Graph 内部,decode 的 79 个 verify graph
(每个 25-31 ms)在 kernel 表里是"空洞",初看像 50% GPU 空闲;
`--cuda-graph-trace=node` 展开后,**真实利用率 79-89%,graph 内节点间隙合计
<0.1 ms**。

每轮(35 ms wall,92 轮/256 tok)构成:

| 项 | 时间 | 占比 | 判定 |
|---|---|---|---|
| vec::kernel(GGML vec GEMV,target+draft) | 21.2 ms | 76.6% kernel | **带宽受限**,见 §3 |
| q8_ksplit_mma(draft 的 Q8 平面,tensor core) | 3.5 ms | 10.2% | 127 GB/s 低效但量小(~1% 端到端) |
| attention + GDN + rmsnorm + quantize 等 | ~4 ms | ~15% | 小核,量已不大 |
| **轮间大停顿(95 个,~3.3 ms/轮)** | 3.3 ms | 9.4% wall | host 串行依赖,见 §4 |

## 3. GEMV 核:已到带宽墙,无核级空间

独立微基准(复用 sm_89 构建的 `ggml_bridge.cu.o` + 19 个 `ggml_vec_*.cu.o`
链接 standalone bench;`gemv_bench_sm89.txt`):

| 类型 | 17408×5120 t=5 GB/s | 说明 |
|---|---|---|
| IQ3_S (t21) | 733 | decode 最大头 |
| IQ4_XS (t23) | 1128 | L2 加成(权重 47 MB < 96 MB L2) |
| IQ3_XXS (t18) | 668 | |
| Q4_K (t12) | 1224 | |
| Q6_K (t14) | 693 | |

t=1 数值(1100-2200 GB/s)超过 DRAM 峰值,是 96 MB L2 缓存权重所致;
t=5 已接近/达到 ~950 GB/s 峰值。在上下文里(13.4 GiB 流式读、无 L2 复用),
vec::kernel 有效带宽 ≈ 13.4 GiB ÷ 21.23 ms ≈ 630-700 GB/s(峰值 66-73%)。

**V100 的 L1I unroll 修复在这里没有对应物**:Ada 的指令缓存足够大,
T≥6 的 vec 核不受指令吞吐限制。这与 4080S 上 1.6.5→1.7.0 A/B 零差异
(接受率、输出流逐字节相同,吞吐 ±4%)互相印证——+18.9% 的 GGML 收益
是 Volta L1I 专属,不随代码行传播到 sm_89。

## 4. 唯一实质性剩余空间:轮间串行依赖(~10%)

96% 的空闲集中在 95 个轮间大停顿(每轮 ~3.3 ms):上一轮 graph 完成后,
host 端做采样结果处理、MTP/dflash2 记账、组装下一轮 graph 参数,
期间 GPU 空转。这是**数据依赖的串行段**(下一轮 draft 取决于本轮接受
token),不是 launch 开销(graph 内 8.9 万个小间隙合计仅 6 ms)。

要拿掉它需要引擎级改造:采样/接受判定留在 GPU 端、下一轮 graph 参数
走设备侧间接引用,使第 N+1 轮 graph 的入队不被 host 处理阻塞。
预期收益 ~9%(3.3/35 ms),属周级工程,不是本次交付范围;
记录在此作为后续候选。

## 5. 结论

1. 生产配置(`ch2048 K5 int8 dflash2 lm-head-draft`)已是 4080S 最优点,
   维持不变。
2. decode 94 tok/s 的主要成本是 13.4 GiB 权重的每轮 DRAM 读取(带宽受限,
   66-73% 峰值);核级、量化格式级(换更宽核/改 unroll)均无空间。
3. 唯一可测的剩余空间是轮间串行段(~10%),需要引擎级 graph 流水线改造,
   列为后续候选,本次不做。
4. 本次未改任何产品代码;4080S 服务已恢复 `ninfer:1.7.0-sm89` 并验证
   HTTP 200。
